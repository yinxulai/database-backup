# TASK-0011 Design: Multi-Schema Backup Support

## Overview

**Task**: 评估并设计多 schema 备份支持
**Status**: IN_PROGRESS
**Date**: 2026-04-24

---

## 1. 背景与目标

### 现状

当前 `BackupSource` 支持：
- `tables?: string[]` - 按表筛选（支持 `schema.table` 格式）
- 全库备份（不设置 `tables` 时）

不支持按 schema 筛选。

### 目标

在不破坏当前简洁 YAML 模型的前提下，支持同时备份多个 schema，满足以下场景：
- 一个 PostgreSQL 数据库包含多个业务 schema（`public`, `audit`, `analytics` 等）
- 用户只需备份其中部分 schema，而非整个数据库

---

## 2. 配置设计

### 2.1 配置字段

在 `BackupSource` 中新增两个互斥字段：

```typescript
// 单 schema（向后兼容）
schema?: string

// 多 schema（新增）
schemas?: string[]
```

### 2.2 配置规则

| 配置 | 含义 |
|------|------|
| 不设置 `schema`/`schemas` | 备份整个数据库（保持当前行为） |
| 设置 `schema: "public"` | 仅备份 public schema |
| 设置 `schemas: ["public", "audit"]` | 同时备份 public 和 audit 两个 schema |
| `schema` 与 `schemas` 互斥 | 不可同时配置，校验时抛出错误 |

### 2.3 与 `tables` 的组合规则

**优先级：`schemas` > `schema` > `tables`**

| 配置组合 | 行为 |
|----------|------|
| `schemas: ["public"]` | 备份 public schema 下所有对象 |
| `schemas: ["public"], tables: ["users"]` | 备份 public schema 下的 users 表（视为 `public.users`） |
| `schemas: ["public"], tables: ["audit.logs"]` | 备份 audit schema 下的 logs 表（限定名优先） |
| `tables: ["users", "audit.logs"]` | 跨 schema 混合筛选（不设置 schemas 时） |

**关键原则**：
- `tables` 中带 `.` 的视为完全限定名（`schema.table`），忽略 `schemas` 设置
- `tables` 中不带 `.` 的表名，结合 `schemas` 筛选（未设置时使用默认 search_path）

### 2.4 示例 YAML

```yaml
# 单 schema 备份
name: app-backup
source:
  type: postgresql
  connection:
    host: localhost
    port: 5432
    username: postgres
    password: ${DB_PASSWORD}
  database: app
  schema: public  # 旧写法，保持兼容

---
# 多 schema 备份
name: multi-schema-backup
source:
  type: postgresql
  connection:
    host: localhost
    port: 5432
    username: postgres
    password: ${DB_PASSWORD}
  database: app
  schemas:
    - public
    - audit

---
# 多 schema + 表筛选
name: selective-backup
source:
  type: postgresql
  connection:
    host: localhost
    port: 5432
    username: postgres
    password: ${DB_PASSWORD}
  database: app
  schemas:
    - public
    - audit
  tables:
    - users           # → public.users（由 schemas 限定）
    - audit.logs      # → audit.logs（完全限定名，优先于 schemas）
```

## 4. 校验规则

### 4.1 `scanner.ts` 新增校验

```typescript
// validateSource 中新增
private validateSourceSchema(source: Record<string, unknown>, prefix: string, errors: ValidationError[]): void {
  const schema = source.schema as string | undefined
  const schemas = source.schemas as string[] | undefined

  // 互斥校验
  if (schema !== undefined && schemas !== undefined) {
    errors.push({
      path: `${prefix}`,
      message: 'schema 与 schemas 只能使用其中之一，不能同时配置',
    })
  }

  // schemas 格式校验
  if (schemas !== undefined) {
    if (!Array.isArray(schemas)) {
      errors.push({
        path: `${prefix}.schemas`,
        message: 'schemas 必须是字符串数组',
      })
    } else if (schemas.some((s) => typeof s !== 'string' || !s.trim())) {
      errors.push({
        path: `${prefix}.schemas`,
        message: 'schemas 数组中的每个元素必须是非空字符串',
      })
    }
  }
}
```

## 5. 实现方案

### 5.1 PostgreSQL Driver (`postgresql.ts`)

**变更 `buildPgDumpArgs`**：

```typescript
private buildPgDumpArgs(options: DumpOptions, destFilePath: string): string[] {
  const args: string[] = []

  // 连接参数（不变）
  args.push('-h', this.connection.host)
  args.push('-p', String(this.connection.port))
  args.push('-U', this.connection.username)
  args.push('-d', options.database || this.connection.database)

  if (this.connection.ssl) {
    args.push('--ssl-mode=require')
  }

  // ── Schema 参数（新增）─────────────────────────────
  if (options.schemas && options.schemas.length > 0) {
    for (const schema of options.schemas) {
      args.push('-n', schema.trim())
    }
  }

  // Table 参数（现有逻辑不变）
  if (options.tables && options.tables.length > 0) {
    for (const table of options.tables) {
      args.push('-t', table.trim())
    }
  }

  // 压缩与输出（不变）
  if (options.compression === 'gzip') {
    args.push('--compress=9')
  }
  args.push('-f', destFilePath)

  return args
}
```

**pg_dump 多 schema 行为说明**：
- `-n schema` 可重复使用，pg_dump 会导出所有指定 schema
- 多个 `-n` 等价于 OR 语义（取并集）
- 与 `-t` 混用时，pg_dump 会导出匹配 schema 下匹配的表

### 5.2 Executor 变更 (`executor.ts`)

**变更 `stageDump`**：

```typescript
private async stageDump(ctx: BackupContext): Promise<void> {
  const { source, destination, destinations } = ctx.config.config
  const primaryDest = destinations?.[0] ?? destination
  
  const dumpOptions: DumpOptions = {
    database: source.database,
    schemas: source.schemas ?? (source.schema ? [source.schema] : undefined),
    tables: source.tables ?? [],
    compression: primaryDest?.type === 's3' ? 'gzip' : undefined,
  }

  ctx.result.tables = source.tables ?? []
  ctx.result.schemas = dumpOptions.schemas  // 记录备份的 schema

  ctx.stagedFile = await this.withRetry(
    () => this.dumpToTempFile(ctx.dbDriver, dumpOptions, ctx.log),
    'DUMP_FAILED',
    ctx.log
  )

  ctx.result.size = ctx.stagedFile.size
}
```

## 6. 文件命名与日志

### 6.1 文件 Key 生成

当使用多 schema 时，key 生成逻辑保持现有结构，仅在 metadata 中记录 schema 信息。

**实际行为**：
- Key 格式：`{prefix}/{db_type}/{database}/{date}/{task_name}-{time}.sql.gz`
- schema 信息通过 `BackupResult.schemas` 记录，不直接体现在 key 中

### 6.2 日志输出

```typescript
ctx.log.info('Starting database dump', {
  database: dumpOptions.database,
  schemas: dumpOptions.schemas,  // 新增

})
```

## 7. 恢复边界

### 7.1 恢复行为

- **整库恢复**：使用 `pg_restore` 或 `psql` 直接恢复整个 dump 文件
- **表级恢复**：通过 `-t table` 参数指定要恢复的表（pg_restore 支持）
- **Schema 恢复**：无法从 dump 中单独提取 schema，所有 schema 一起恢复

### 7.2 限制说明

1. 多 schema dump 的恢复**不支持 schema 级别的选择性恢复**
2. 如需单 schema 恢复，建议拆分为多个独立备份任务
3. 表级恢复（`-t`）在多 schema dump 中可用，但需要完整限定名

| # | 标准 | 验证方式 |
|---|------|----------|
| 1 | 单 schema 配置（`schema: "public"`）行为与原来全库备份不同 | 配置校验通过 + pg_dump 参数正确 |
